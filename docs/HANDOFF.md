## 1. Что это

Android-приложение: **офлайн-чат по Википедии**. Локальная языковая модель (GGUF,
~4B параметров, Q4_0) отвечает на вопросы по полнотекстовому поиску в русской
Википедии в формате ZIM (Kiwix). Всё на телефоне, без сети. Модель считается на
**NPU Qualcomm Hexagon** через llama.cpp.

Путь запроса:

```
вопрос
  ├─ FactoidAnswerer: вопрос-факт + сущность найдена + в карточке статьи есть
  │  нужное поле → ответ прямо из инфобокса, без модели          (~0.1–0.4 с)
  └─ ZIM-поиск (BM25 libkiwix + пробы по заголовкам + mE5-реранк)
     → 4 статьи (карточка + тело) в промпт → llama.cpp на NPU     (~9–18 с)
```

## 4. Главные открытые проблемы — по важности

**4.1. Мастер llama.cpp убивает DSP на S23 (v73) с 2026-09-16.**

первом `llama_decode` любой модели, включая Q4_0:

`82324fc5` (#28995) живёт, соседний `1ec81880` падает. Не помогли:

DMA-копии (гипотеза опровергнута бисектом). Трасса: батч #1 префилла (слои 0–12,

## 6. Ограничения платформы — уже выучено, не переоткрывать

- **Только нативный Q4_0.** K-кванты на нашем пине уходят на CPU (0.4 против ~8 tok/s);
  на мастере Q4_K/Q6_K перепаковываются в Q4_0 — та же скорость, хуже качество.
- **≤4B параметров**: 7–8B не грузятся (`HTP0 buffer mapping failed`), одна NPU-сессия
  маппит ~3.5 ГБ. На S23 под модель ~2.5 ГБ свободной памяти.
- **KV-кэш только F16** — квантованный KV тихо уводит внимание на CPU.
- `flash_attn_type = AUTO`, `n_ubatch = 1024` — так у Qualcomm, вместе вдвое ускорили prefill.
- `ADSP_LIBRARY_PATH` ставится в `WikiLLMApplication.onCreate`, иначе `0x80000406`.
- `useLegacyPackaging=true`, иначе бэкенд не находит свои `.so`.
- MTP-функции (`llama_set_embeddings_nextn` и др.) объявлены **без** `extern "C"` —
  иначе не грузится весь `libllm.so`. MTP даёт только 1.18× на S23 (n_max=1 оптимум),
  в замерах выключен.
- Phi-4 роняет бэкенд (scaled rotary). GPU (OpenCL/Adreno) всегда ≤ CPU — тупик.
- Сэмплер сбрасывается между генерациями (`llama_sampler_reset`) — исправлено 09-01.
- Промпт: короткий ответ (1–3 предложения), история — последние 3 обмена,
  кореференция («там/его») переписывает вопрос; «Думать» выключено — всё это вместе
  дало 4.5× к ходу 09-01.

## 7. Как работать с проектом

### 7.1. Сборка и установка

```bash
cd /Users/igormorozov/Projects/wiki-llm-android
gh workflow run hexagon-app.yml --ref main                               # пин из файла
gh workflow run hexagon-app.yml --ref main -f llama_ref=<sha> -f patchset=default   # другой llama.cpp
gh run watch <run-id> --exit-status
```

Скачивание артефакта: `gh run download` на этом Mac часто висит (скорость ~50 КБ/с – 1.5 МБ/с).
Надёжно так — взять redirect через API и качать `curl -C -` с повторами:

```bash
AID=$(gh api repos/akozit-del/wiki-llm-android/actions/runs/<run>/artifacts --jq '.artifacts[]|select(.name=="wiki-llm-hexagon-apk")|.id')
LOC=$(curl -s -o /dev/null -w '%{redirect_url}' -H "Authorization: Bearer $(gh auth token)" https://api.github.com/repos/akozit-del/wiki-llm-android/actions/artifacts/$AID/zip)
curl -sS -L -C - --max-time 600 -o apk.zip "$LOC"     # повторять до успеха
adb -s <serial> install -r wiki-llm-hexagon-*.apk
```

Workflow умеет применять локальные патчи к llama.cpp: `app/src/main/cpp/patches/<patchset>/*.patch`
(сейчас есть только пустой `default`). Кэш нативной сборки учитывает `llama_ref`,
`patchset` и сами патчи.

| Скрипт | Что | Время |

| `run_model_turns.sh <serial> 1` | 13 вопросов, доходящих до модели | 3–20 мин |

### 7.3. Особенности устройств и adb

- `adb shell input text` не принимает кириллицу на Samsung. Вопросы шлются интентом:
  `adb shell "am broadcast -n com.wikillm.android.debug/com.wikillm.android.diag.BenchmarkReceiver -a com.wikillm.android.ASK --es q 'вопрос'"` (вложенные кавычки обязательны).
- Логи: `adb logcat` (теги `ChatVM`, `WikiLLM`, `ggml-hex`) и
  `adb shell "run-as com.wikillm.android.debug cat files/diag.log"` (рулонный, 256 КБ —
  содержит и прошлые прогоны, отсюда `--turns`).
- Debug-сборка читает переменные бэкенда из системного свойства:
  `adb shell setprop debug.wikillm.env 'GGML_HEXAGON_OPTRACE=1;GGML_HEXAGON_MM_SELECT=1'`,
  затем `am force-stop`. Сброс — `setprop debug.wikillm.env -` (пустое значение setprop не
  принимает). Забытое свойство тихо меняет все следующие замеры.
- После переустановки RAG может оказаться выключен — включить переключатель в чате
  (координаты на S23 и S26 разные, искать через `uiautomator dump`).
- S26: при первом подключении — запрос «Разрешить отладку по USB» на экране; `adb install`
  может висеть на диалоге Google Play Защиты «Проверить безопасность приложения?» — нажать
  «Проверить это приложение».
- S26: ZIM выбирается через SAF, из adb этого не сделать — поэтому копия в `files/zim/`.
- `adb shell svc power stayon usb` — чтобы экран не гас во время прогона.
- После 4–5 часов прогонов S23 греется до 48 °C и троттлит — такие замеры не сравнивать.
- Модель выбирается выпадающим списком вверху экрана чата (тап по заголовку, затем по
  пункту — координаты брать из `uiautomator dump`).

### 7.4. Краш-проба (одна попытка, ~2 мин)

Установить APK → `am force-stop` → `logcat -c` → запустить приложение → дождаться
`ChatVM: Model loaded` → отправить один вопрос интентом → ждать в `logcat` либо
`[TURN] end` (выжил), либо `Fatal signal` / `status notification 3` (упал).

### 7.5. Окружение Mac (грабли)

- Шелл агента — zsh: URL с `?` надо брать в кавычки (иначе «no matches found»).
- Нет `timeout`; `sed -i ''` (BSD); нет локального JDK/Gradle.
- `github.com` временами не резолвится системой (mDNSResponder) — проверить
  `git ls-remote origin HEAD`; обход — Git Data API (подробно в памяти, файл
  `project_git-push-dns-workaround.md`).
- Mac на батарее засыпает через минуту — фоновые задачи молча пропускаются.

### 7.6. Соглашения

- Коммит: `область: что изменилось` (`rag:`, `llm:`, `chat:`, `bench:`, `build:`, `docs:`),
  тело объясняет *почему* и приводит замеры. Последняя строка — `Co-Authored-By: …`.
- Комментарии в коде — «почему», а не «что».
- **Неверный быстрый ответ хуже промаха** — в `FactoidAnswerer` любая неуверенность → null.
- Замер до отгрузки. Один проход по 13 вопросам — не доказательство: разброс между
  проходами одной сборки ±15 %, recall@1 ±3 п.
- После коммита в документы или результаты — `./benchmark/publish_drive.sh`
  (пользователь читает из Drive). `.git` в Drive не переносить.
- `benchmark/LATEST.md` — журнал замеров (новые записи сверху, ≤ ~40 строк на запись,
  только реально измеренное, «не измерено» так и пишется).

- Для нетривиальных изменений: сначала изучить, как это решают в больших системах,
  дать 2–4 варианта, рекомендовать, и строить только после согласия.
- Не любит долгих пауз — во время долгой работы писать, на каком шаге.
- Против лишней сложности: если существующее решает задачу — не надстраивать.
- Объяснять термины простым языком, когда спрашивает («что такое пин», «бамп»).
- **Внешние действия только с явного «да»**: публикация issue/PR в чужих репозиториях,
  сообщения, покупки. Сборки в своём CI и установка на свои тест-телефоны — можно.
- Ритм: один спринт в неделю (обычно суббота) + автоматический обзор по воскресеньям.
  Спринт завершается записью в `LATEST.md`, обновлением `CLAUDE.md` при изменении
  состояния и `publish_drive.sh`.
